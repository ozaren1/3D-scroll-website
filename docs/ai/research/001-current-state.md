# 001 — Текущее состояние проекта и выбор стека бэкенда
Дата: 2026-10-24

## Кратко
Фронтенд — сырой прототип: одна клиентская страница, 5 захардкоженных кадров (3 видео, 2 lorem-текста), Z-скролл на накоплении дельты. Бэкенда нет. Для бэкенда берём NestJS 12 + SQLite (better-sqlite3) без ORM: данных мало, нужна простая установка на один сервер и тесты без Docker.

## Факты (репозиторий)
- `package.json`: next 15.0.4, react 19, gsap, clsx, sass, embla-carousel-react (не используется), tailwind (не используется — нет `@tailwind` в css).
- `src/app/page.tsx`: `"use client"`, `useLayoutEffect`, на `scroll` считается `delta` и прибавляется к `zVals[i]` (×-4). Проблемы:
  - позиция зависит от истории событий, а не от `scrollTop` → дрейф при быстрой прокрутке/перезагрузке посередине страницы, нет обратимости;
  - анимация через CSS `transition: all .75s` на каждый кадр → лаги, «резиновость»;
  - прозрачность 0/1 скачком, нет глубины (затухание, размытие);
  - высота `body` захардкожена `--depth: 4000px` и не зависит от числа кадров;
  - все 3 видео (~55 МБ) автоплеятся одновременно, даже далёкие;
  - нет заголовка, имени, навигации, описаний работ, контактов; `layout.js` — «Create Next App»; шрифт `raleway_c` не подключён, Geist подключён, но не используется;
  - нет `prefers-reduced-motion`, нет доступности (alt, aria), нет мобильной адаптации кроме скрытия смещений.
- `src/app/data.ts`: тип `Frame { id, content, src, position, background, text, type }`.
- `public/assets/video/{1,2,3}.mp4` — 28 МБ, 1.2 МБ, 25 МБ. `1.mp4` не используется. ffmpeg на машине нет (постеры генерировать нечем).
- Нет тестов, нет `.env`, нет Docker.

## Факты (версии npm на 2026-10-24, `npm view`)
- @nestjs/core 12.2.0, @nestjs/cli 12.0.10, @nestjs/config 12.0.1, @nestjs/jwt 12.0.3, @nestjs/throttler 6.7.1.
- prisma 8.0.0-rc / @prisma/client 7.10 (мажорная смена API в 7: driver adapters, `prisma.config.ts`).
- typeorm 1.1.2 (новый мажор), better-sqlite3 13.0.3, bcryptjs 3.0.3.

## Варианты хранилища
1. **Prisma + PostgreSQL** — привычно, но нужен Docker/сервер БД; Prisma 7/8 в переходном состоянии.
2. **TypeORM 1.x** — новый мажор, миграции тяжеловесны для 3 таблиц.
3. **better-sqlite3 + тонкие репозитории + SQL-миграции** — ноль инфраструктуры, синхронный быстрый доступ, тесты на `:memory:`, бэкап = копия файла.

## Риски
- SQLite не для горизонтального масштабирования — для портфолио неактуально.
- better-sqlite3 — нативный модуль; при отсутствии prebuilt под платформу нужна сборка (python/make).
- Видео большие — отдавать их через Node неоптимально; в проде лучше nginx/CDN перед `/media`.

## Рекомендация
Вариант 3. Слой доступа к данным изолировать в `*Repository`, чтобы переезд на Postgres был локальной заменой.
