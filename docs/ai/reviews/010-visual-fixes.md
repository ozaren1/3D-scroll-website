## Что проверено и в порядке

- **Новый эндпоинт.** `JwtAuthGuard` стоит на `PUT /api/admin/process` (`process.controller.ts:15`), e2e проверяет 401. Контракт плана 010 выполнен: значения по умолчанию без записи в БД, обрезка пробелов, 400 на пустой этап и на 9 этапов. Глобальный `ValidationPipe` с `whitelist` и `forbidNonWhitelisted` действует. Отдельно прогнал DTO на `{items:[null]}` и `{items:["x"]}`: оба дают ошибку валидации, до `items.map` они не доходят.
- **`/media` в Caddy.** Имена файлов — `uuid.<ext>` из сигнатуры, типы только mp4/webm/jpg/png/webp, поэтому svg и html на origin не попадут. Папка плоская, временные файлы `.upload-*` закрывает `@hidden` (`path_regexp` работает по пути уже после `handle_path`). `browse` не включён. Официальный образ `caddy:alpine` ставит `mailcap`, так что mp4 и webm получают верный `Content-Type` (проверено по `Dockerfile.tmpl` в caddy-docker). `encode` видео не сжимает, Range работает.
- **Что доступно снаружи.** Caddy монтирует только `uploads` и только на чтение. `data` и `.env` в него не смонтированы. Порты `api` и `web` наружу не опубликованы. В `web` нет `env_file`, поэтому секретов в окружении фронта нет.
- **Секреты в образах.** `.env*` исключены в обоих `.dockerignore`, контекст дополнительно ограничен `git archive`. В `backend/.npmrc` токенов нет. `set-admin.sh` передаёт пароль через окружение, а не argv.
- **`SITE_ADDRESS` с двумя адресами.** Caddy подставляет `{$VAR}` до разбора файла, и значение может давать несколько токенов (документация Caddy, Caddyfile Concepts). Compose разбирает значение с запятой и пробелом и в кавычках, и без них (проверено выше). При смене значения контейнер пересоздаётся через `up -d`.
- **`API_URL` и `SITE_URL`.** Читаются из `process.env` на сервере и в сборку не вшиваются; вшивается только пустой `NEXT_PUBLIC_API_URL`. Страницы с `revalidate = 60` (и `/works`, динамическая из-за `searchParams`) подхватывают их при рендере. Исключения — `robots.txt` и первый ответ после выкладки, см. №2 и №3.
- **Standalone-образ.** Есть `server.js`, трассированные `node_modules`, `.next/static`, `public`. `.next` принадлежит `node`, запись ISR возможна. Шрифты `next/font` скачиваются при сборке и лежат в `static`. `next/image` в коде не используется.
- **Большие загрузки.** В Caddy нет ограничения тела запроса и буферизации; `requestTimeout` Node поднят до 2 ч (`main.ts:12`), предел задаёт multer.
- **`LiveVideo`.** Очистка в эффекте правильная (`pause` → снять `src` → `load`), отклонённый `play()` перехвачен, таймер и наблюдатель снимаются. Гонка `play()`/`load()` в `ExampleButton` безопасна: `AbortError` перехвачен.
- **Остальные шаги плана.** Меню центрируется (`.menu` на десктопе скрыт, в сетке три элемента). Блик обрезается по `--tilt-clip` (наследуется в TiltCard и в Services, и в About). Поля входа и описание в плеере сделаны по плану. Классы в `ProcessAdmin` все есть в `admin.module.scss`.

## Замечания

### Блокирующие

**1. [БЛОКИРУЕТ] Критические уязвимости Next.js на публичном сервере** — `package.json:15`, `package-lock.json` (`next 15.0.4`, `react 19.0.0`).
Последствие: `npm audit` показывает для этой версии GHSA-9qr9-h5gf-34mp (RCE без авторизации через протокол React Flight, затрагивает App Router; патч в ветке 15.0.x — 15.0.5, подтверждено в блоге Next.js по CVE-2025-66478; уязвимость массово эксплуатируется). Там же GHSA-2xp9-vwfh-vxw4 и GHSA-2464-fhr4-w9xw: RCE без авторизации через Image Optimization API (`<15.5.24` и `<=15.5.27`). Эндпоинт `/_next/image` включён по умолчанию, хотя сайт его не использует. Контейнер `web` работает от `node`, секретов в окружении и смонтированных данных у него нет, но атакующий может подменять страницы, в том числе перехватить пароль и JWT при входе в админку, и обращаться к `api:4000` изнутри сети Compose.
Исправление:
- Обновить `next` и `eslint-config-next` до `15.5.29` (версия из `npm audit`, та же мажорная ветка), `react` и `react-dom` — до последнего патча 19.x. Минимальное `15.0.5` закрывает только первую уязвимость.
- Дополнительно закрыть неиспользуемый оптимизатор: `images: { unoptimized: true }` в `next.config.mjs` и/или `respond /_next/image* 404` в Caddyfile.
- После обновления прогнать `next build`, tsc, lint и QA: скачок с 15.0 до 15.5 затрагивает сборку.
- Сервер уже 8 дней работает с уязвимой версией, поэтому перед пересозданием контейнера `web` снять `docker logs` и `docker top` (пересоздание уничтожит следы). После выкладки сменить `JWT_SECRET`, а пароль админа задавать через `set-admin.sh` только после патча.

### Неблокирующие: закрыть до подключения домена

**2. `robots.txt` навсегда зафиксирован на этапе сборки, `sitemap.xml` час отдаёт localhost** — `src/app/robots.ts:6`, `src/app/sitemap.ts:5`, `src/lib/seo.ts:6`.
Последствие: при сборке в Docker нет `SITE_URL`. Метаданные-маршруты статичны по умолчанию (`next/dist/export/routes/app-route.js:80`), поэтому в `robots.txt` строка `Sitemap:` не появится и после смены `SITE_URL`. `sitemap.xml` с `revalidate = 3600` после свежей сборки первый час отдаёт URL `http://localhost:3001/...` и резервные категории.
Исправление: `export const dynamic = "force-dynamic"` в обоих файлах, `revalidate` в sitemap убрать.

**3. После каждой выкладки первый ответ страниц — демо-контент сборки** — `Dockerfile:8-9`, `src/lib/api.ts:12`, `deploy/deploy.sh:17`, `deploy/compose.yaml:25-26,42-44`.
Последствие: во время сборки API нет, поэтому страницы пререндерятся с `fallbackProjects` и без canonical, а новый контейнер начинает с этого кэша. Первый посетитель получит чужие демо-работы; перегенерация начнётся после его запроса. Если в этот момент API ещё стартует (`depends_on` без healthcheck), демо-контент закрепится ещё на 60 с. То же произойдёт при смене домена: `web` пересоздаётся из того же образа.
Исправление: добавить в `api` healthcheck по `/api/health` и `condition: service_healthy` для `web`, а в конец `deploy.sh` — прогрев `curl` по `/`, `/about`, `/works` и категориям, дважды.

**4. Выкладка не применяет изменения Caddyfile** — `deploy/deploy.sh:13-17`, `deploy/compose.yaml:38`.
Последствие: bind-монтирование файла держится за старый inode, а `mv app app.old` путь не меняет, поэтому хеш конфигурации тот же и `up -d` контейнер `caddy` не пересоздаёт. Правка Caddyfile (в том числе из №1) молча не вступит в силу, пока контейнер случайно не перезапустится; при этом проявится всё накопленное.
Исправление: в `deploy.sh` после `up -d` вызывать `docker compose up -d --force-recreate caddy` или монтировать каталог вместо файла. `caddy reload` не поможет: он читает тот же старый inode.

**5. Адрес `www` и HTTPS** — `deploy/Caddyfile:3,23-27`, `deploy/README.md:32`.
Последствие: `www` отдаёт полную копию сайта без редиректа на основной домен (дубль для поисковиков; canonical смягчает). После включения HTTPS нет HSTS. Запятая обязательно должна сопровождаться пробелом: `a.ru,www.a.ru` Caddy прочитает как один адрес (документация требует хотя бы один пробел).
Исправление: отдельный блок с `redir https://домен{uri} permanent` для `www`, заголовок `Strict-Transport-Security`; в README отметить пробел.

### Неблокирующие: для владельца

**6. Portainer открыт в интернет по HTTP** — `deploy/README.md:38`.
Последствие: Portainer управляет Docker на этой машине. Его компрометация (или перехват пароля по HTTP) даёт доступ к `/opt/portfolio/.env`, SQLite и всем контейнерам; ufw его не защищает, потому что Docker публикует порты в обход. Контейнер чужой, поэтому не трогал, но это самая широкая поверхность на сервере после №1.
Исправление: решение владельца — привязать порт к `127.0.0.1` и ходить через SSH-туннель либо ограничить через `DOCKER-USER`.

### Неблокирующие: код

**7. Видео в услугах запускается без наведения** — `src/components/Services/Services.tsx:42`.
Последствие: расходится с планом и с комментарием в строке 26 («только наведение или фокус с клавиатуры»). `onFocus={start}` срабатывает на любой фокус: при тапе на Android и — главное — когда `dialog.close()` возвращает фокус на кнопку после закрытия плеера. Видео играет и тянет трафик до потери фокуса.
Исправление: `onFocus={(e) => e.currentTarget.matches(":focus-visible") && start()}`.

**8. Спираль без JS и до гидратации — стопка карточек** — `src/components/WorkSpiral/WorkSpiral.module.scss:76`, `WorkSpiral.tsx:108`.
Последствие: значения `--r` по умолчанию убраны из CSS. `translateZ(var(--r))` без значения делает весь `transform` недействительным, и 14 карточек лежат друг на друге до выполнения эффекта (на слабых телефонах — секунды, без JS — всегда). Раньше CSS задавал радиус сам.
Исправление: вернуть в `.helix` `--r: min(620px, 42vw)` и `--r: 46vw` в медиазапросе; инлайновое значение из JS их перекроет.

**9. Фоновое видео продолжает играть под плеером** — `WorkSpiral.tsx:156-170,254`.
Последствие: при открытом плеере со звуком работа спирали продолжает скачиваться и декодироваться, идут два потока одного файла. На телефоне и при одном VPS это заметно. Замечание тянется с ревью 002. Заодно `LiveVideo` грузит исходный файл (до `MAX_VIDEO_MB`) и не учитывает `navigator.connection.saveData`.
Исправление: отдавать из контекста плеера признак «открыт» и обнулять `live`; при Save-Data не запускать.

**10. Выкладка может уйти без новых файлов** — `deploy/deploy.sh:8`.
Последствие: `git diff --quiet HEAD` не видит неотслеживаемые файлы. `backend/src/process/`, `src/components/admin/ProcessAdmin.tsx` и план пока untracked; при коммите только отслеживаемых (`git add -u`) сборка на сервере упадёт (старые контейнеры продолжат работать, но код в `app` уже заменён).
Исправление: координатору при коммите добавить эти пути; в скрипте проверять `git status --porcelain` и прерываться.

**11. Контракт не записан в DECISIONS** — `docs/ai/DECISIONS.md`, план 001 «Контракт API».
Последствие: `core.md` требует менять контракт через planner с записью в `DECISIONS.md`; про `/process` там ничего нет, контракт есть только в плане 010.
Исправление: добавить запись и дополнить контракт плана 001.

**12. Кеш ошибок в `/media`** — `deploy/Caddyfile:11`.

**13. Комментарий про таймаут не соответствует стеку** — `backend/src/main.ts:11-12`.
Последствие: сказано, что прокси сам обрывает медленных клиентов, но у Caddy по умолчанию нет таймаута чтения тела, так что медленный запрос без токена держит соединение до 2 ч. Для этого масштаба риск низкий.

**14. Эксплуатация** — `deploy/compose.yaml`, `deploy/deploy.sh:18`.
